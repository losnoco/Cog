# Cog for iOS

The iOS build shares Cog's sources. `CogAudio` and the projects under
`Frameworks/` build for macOS and iOS alike. The plugins, which macOS loads
as bundles, are compiled on iOS into one framework, `CogPlugins`.

## Getting started

```sh
git submodule update --init --recursive
iOS/prepare.sh
```

`prepare.sh` applies the patches in `iOS/patches/` to submodules. It also
builds the iOS third-party libraries into `ThirdParty/*/ios/`, which are not
committed, by running `Scripts/build-ios-libraries.sh` (a few minutes, needs
`brew install cmake`).

## Layout

- `CogPlugins.xcodeproj`: the plugins as one iOS framework, plus
  `CogPluginsTests`.
  - The project is generated by `generate_plugins_project.py`. To add or
    change a plugin, edit `PLUGINS` there and run the script again; don't
    edit the project in Xcode.
  - `PluginController` finds the plugin classes at launch among those of the
    loaded images.
- `CogPlugins/`: the framework's prefix header and build settings.
- `CogPluginsTests/`: tests that find, decode and play through the plugins
  on the iOS Simulator.
- `patches/`: changes to submodules that the iOS build needs.

## Porting more of Cog

- A project under `Frameworks/`:
  - `Scripts/make-multiplatform.py` makes its targets build for iOS too.
  - `Scripts/link-ios-libraries.py` links the iOS builds of the
    `ThirdParty/` libraries it uses, leaving the macOS ones to macOS.
- A library in `ThirdParty/`: add a `build_<name>` function to
  `Scripts/build-ios-libraries.sh`, with the release and patches its
  `README.md` names.
- After changing plugin sources, check that the macOS app still builds.

## Differences from macOS

- No exclusive output or DoP. Everything is resampled to the audio session's
  rate.
- 2SF (vio2sf) runs without its JIT, as iOS allows no executable memory.
- MIDI's Apple synth is MIDISynth, as iOS has no DLSSynth. Its SoundFonts
  are the app's resources, as on macOS.
